# .github

> Contains GitHub Actions workflows for CI/CD, demo generation, and package publishing.

The .github directory holds YAML configuration files for GitHub Actions workflows that automate testing, linting, evaluation, frontend building, demo site generation, and PyPI package publication. These workflows ensure code quality, validate deployments, and maintain project infrastructure.

## Files

### `.github/workflows/ci.yml`

Defines continuous integration workflow for linting, testing, and validation across multiple platforms and Python versions.

- `lint-and-test` (job) - Runs ruff linter and pytest suite on multiple OSes and Python versions.
- `rag-eval` (job) - Executes retrieval evaluation tests (non-blocking) to detect regressions.
- `frontend` (job) - Builds the frontend using Node.js to ensure UI components compile correctly.
- `wheel` (job) - Validates that the built wheel includes the frontend static files for serving.

### `.github/workflows/demo.yml`

Manually triggered workflow to generate and deploy a demo wiki to GitHub Pages.

- `demo` (job) - Installs repowiki, scans the repository, and publishes the generated wiki site to gh-pages branch.

### `.github/workflows/publish.yml`

Automates PyPI package publication upon new GitHub releases, including frontend build and wheel validation.

- `publish` (job) - Builds frontend, constructs Python package, verifies wheel contents, and publishes to PyPI.

## Key Concepts

- **GitHub Actions**: Automation platform used to run workflows on events like push, pull_request, or release.
- **CI/CD**: Continuous Integration and Deployment processes that test, build, and publish software automatically.
- **PyPI Publishing**: Process of building a Python wheel and uploading it to the Python Package Index for distribution.
- **Demo Generation**: Automated creation of a live wiki demo from the codebase, deployed to GitHub Pages.

## Internal Relationships

- `.github/workflows/ci.yml` → `.github/workflows/publish.yml`: ci.yml validates the build process that publish.yml relies on for PyPI deployment.
- `.github/workflows/ci.yml` → `.github/workflows/demo.yml`: ci.yml ensures code quality before demo.yml can generate and deploy a demo.
- `.github/workflows/publish.yml` → `.github/workflows/ci.yml`: publish.yml uses the same frontend build and wheel validation steps defined in ci.yml.
