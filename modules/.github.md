# .github

> Contains GitHub Actions workflows for CI/CD, demo deployment, and PyPI publishing.

This module defines automated workflows that run on GitHub to ensure code quality, test across environments, build the project, deploy a live demo, and publish releases to PyPI. It includes jobs for linting, testing, frontend building, retrieval evaluation, and artifact verification.

## Files

### `.github/workflows/ci.yml`

Runs continuous integration checks on pushes and pull requests to the main branch.

- `lint-and-test` (job) - Executes linting and testing across multiple OSes and Python versions using ruff and pytest.
- `rag-eval` (job) - Runs retrieval evaluation tests as a non-blocking check to detect regressions.
- `frontend` (job) - Builds the frontend using Node.js to ensure the UI compiles correctly.
- `wheel` (job) - Builds a wheel package and verifies it includes the built frontend files.

### `.github/workflows/demo.yml`

Manually triggers the generation and deployment of a demo wiki to GitHub Pages.

- `demo` (job) - Installs the project, generates a wiki from the repository, and publishes it to the gh-pages branch.

### `.github/workflows/publish.yml`

Automatically publishes the project to PyPI when a new release is created.

- `publish` (job) - Builds the frontend, creates a wheel package, verifies its contents, and publishes it to PyPI.

## Key Concepts

- **Continuous Integration**: Automated testing and linting across multiple environments to maintain code quality and catch issues early.
- **GitHub Pages Deployment**: Uses GitHub Actions to build and deploy a static site (the demo wiki) to GitHub Pages for public access.
- **PyPI Publishing**: Automates the build and release process to PyPI upon tagging a new version, including frontend asset verification.

## Internal Relationships

- `.github/workflows/ci.yml` → `.github/workflows/publish.yml`: Both workflows build the frontend and verify the wheel contains the web UI, ensuring consistency between CI and release artifacts.
- `.github/workflows/demo.yml` → `.github/workflows/ci.yml`: The demo workflow relies on the CI process to ensure the code is functional before generating and deploying the demo.
